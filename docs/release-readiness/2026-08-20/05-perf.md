## 분석
- **지연은 전적으로 node 프로세스 기동(~50ms)이 지배**한다. 1만 이벤트 재생의 실제 알고리즘
  비용은 정상 대비 +6~7ms에 불과(888KB 저널 순차 파싱). 한 요청이 다른 요청을 막는 구조 없음
  (매 훅이 독립 프로세스, 이벤트 루프·커넥션 풀·워커 공유 없음 — 축⑪ 확인).
- **한 작업이 전체를 정지시키는 경로 없음**(축⑤ 최다 출하차단 유형 부재): 서버·큐·공유 워커가
  없다. doctor의 1만 재생도 60ms에 끝나 사용자 체감 정지 없음.
- **메모리**: `readFileSync`로 저널 전량 로드(스트리밍 아님). 1만 이벤트=888KB로 문제없으나,
  이론상 수백만 이벤트 저널이면 전량 버퍼가 한계가 될 수 있다. v0 규모에선 비해당 — 상한
  스트리밍은 로드맵 후속 후보(현 실측 규모에서 결함 아님, 기록).
- **⚠가정 게이트 검증**: 착수 시 G9<150ms·G10 doctor<5s·훅<500ms를 ⚠가정으로 뒀는데, 실측이
  전부 압도적 여유로 충족 → **임계값 완화 불필요**(오히려 실측이 가정보다 훨씬 빠름).

기존 계량 검사(`doc-claims.test.ts`)는 **숫자와 config 키 이름**만 4개 언어에 대조했다.
그래서 문장·불릿이 통째로 빠져도 CI 는 계속 green 이었다.

### 무엇을 어떻게 고쳤나

  4개 언어에서 같아야 하고, 인터프리터 고지(`64 KB`)가 4개 언어에 전부 있어야 한다.
  번역의 «내용»까지는 기계가 못 보지만 **하나가 통째로 없어진 것**은 볼 수 있다.

## ③ G5 — [UX-01] 도움말이 좁은 터미널에서 표 정렬을 잃는다

### 근본 원인

`help.ts` 의 `table()` 이 좌열을 패딩한 뒤 요약문을 **그대로 이어 붙였다.** 173~231자짜리
요약(`doctor`·`tokens gen`·토큰 문서 힌트)은 80열에서 둘째 줄부터 **왼쪽 끝으로 돌아가**
어느 명령의 설명인지 추적할 수 없었다. 앱은 터미널 폭을 **전혀 읽지 않았다**.

### 무엇을 어떻게 고쳤나

1. **접기 + 설명 칸 들여쓰기.** 이어지는 줄이 설명 칸 위치에서 시작한다 — 표가 표로 남는다.
2. **폭 결정**: `COLUMNS` → TTY 폭 → **고정값(100)**. 비TTY 에서 고정값을 쓰는 이유는
   CI 로그와 테스트가 환경에 따라 흔들리면 안 되기 때문이다(결정성). `COLUMNS` 를 먼저 보는
   이유는 파이프 뒤에서 **검증할 수 있는 유일한 손잡이**여서다.
3. **표시 폭으로 잰다** — 한글·CJK·이모지는 한 글자가 두 칸이다. 감사가 [UX-12] 로
   「코드에 있으나 호출 경로가 없다」고 남긴 잠재 결함인데, **접기를 넣는 순간 그 경로가 생긴다.**
   그래서 여기서 함께 닫았다.
4. **긴 사용법 서식**(`critical raise --reason <a|b|c…>` 은 129칸이었다)은 `|`·`,`·`/`·`·`
   같은 **자연 구분자 뒤**에서만 쪼갠다. 아무 데서나 자르면 경로·플래그가 깨져 복붙이 안 된다.

### 재측정 (`evidence/probe-width.js`)

en/ko × COLUMNS 80·100 × 18개 명령군 = **표 행 502개 검사, 폭 초과 0개.** 수정 전에는
같은 조건에서 13개가 넘쳤다(129칸까지).

## ⑤ G10 — [LOGIC-01] 승인 후 고친 산출물로 다음 페이즈에 들어갈 수 있었다

### 근본 원인

`gate.ts` 머리가 선언한 계약 —「승인 후 몰래 고친 문서로 다음 페이즈에 들어갈 수 없다 /
이후 불일치는 게이트 자동 무효화」— 가 **설계 트랙 전이에서 성립하지 않았다.**
`canEnterPhase` 는 `gates[p].status === 'approved'` 만 보고 해시를 재검증하지 않았고,
`invalidateStaleGates` 는 **수동 `harness gate sweep` 한 곳에만** 배선돼 있었다.
`gate verify` 는 드리프트를 정확히 탐지하는데 **아무도 그것을 부르지 않았다.**

설계 영역(`docs/`)은 에이전트가 정당하게 쓰는 곳이므로 이 경로는 실제로 열려 있었다:
사람이 내용 X 를 승인 → 에이전트가 디스크를 Y 로 바꿈 → `phase set P1` 이 exit 0.

### 무엇을 어떻게 고쳤나

`setPhaseViaGate` 가 전이 직전에 `invalidateStaleGates(root)` 를 부른다.
**판정(`canEnterPhase`)이 아니라 변이 쪽에 둔다** — 판정이 순수해야 훅과 CLI 가 같은 규칙을
읽고도 각자 다른 시점에 쓸 수 있고, `invalidateStaleGates` 는 저널에 쓰므로 판정 안에 두면
그 분리가 깨진다. 회귀 테스트가 그 순수성도 함께 고정한다.

## ⑤ G10 — [LOGIC-02] harness 명령이 소유 파일을 덮을 수 있었다

### 근본 원인

`assertOutputAllowed` 가 「루트 안인가」와 「설계 트랙 소스인가」만 봤다. **소유 파일 검사가
아예 없었다.** 그래서 `harness evidence spec … --out .harness/events.jsonl` 이 exit 0 으로
**정본 저널을 생성 스펙 텍스트로 교체**했고, 그 뒤 `harness doctor` 는 `ok: true` 라고 답했다.
`tokens gen/swap --out`·`evidence packet --out` 도 같은 무가드 경로였다.

「소유 파일은 harness 명령으로만 바뀐다」가 **훅 한 곳에만** 살아 있었던 것이 뿌리다 —
이 리포가 반복해 지적한 「두 벌 중 느슨한 쪽이 정본」 패턴이고, `[OPS-76]` 이 정책 파일에서
이미 같은 판단을 내렸다.

### 무엇을 어떻게 고쳤나

1. `STATE_FILES` 정의를 **`policy.ts` 한 벌로** 올렸다(`POLICY_FILES` 옆). `hook.ts` 는 그것을
   가져다 쓴다 — 목록이 표면마다 갈릴 여지를 없앤다.
2. `assertOutputAllowed` 에 소유 파일 거부를 **페이즈 검사보다 위에** 넣었다. 아래 소스 경로
   검사는 설계 트랙에서만 도는데, 소유 파일 보호는 **어느 페이즈에서도 풀리면 안 된다.**

## ② G4 — [API-05] 종료코드가 「판정 아니오」와 「명령 실패」를 구분하지 못했다

### 근본 원인

둘 다 `1` 이었다. `harness ship verdict` 는 출하 게이트라 CI 가 `harness ship verdict || exit 1`
로 쓰는 것이 정상 사용인데, **엉뚱한 디렉토리에서 실행했거나 하위명령을 오타 냈을 때도 정확히
같은 exit 1** 이 나왔다. 스크립트는 「제품이 준비되지 않았다」와 「명령이 아예 돌지 않았다」를
구분할 수 없고, 후자를 전자로 읽으면 릴리스가 멈춘 이유를 오해한다. **어느 문서에도 종료코드
규약이 없었다**(전수 검색 0건).

### 무엇을 어떻게 고쳤나 — 공개 계약 변경

| 코드 | 뜻 |
|---|---|
| `0` | 성공 / 판정이 「예」 |
| `1` | 사용법·환경 오류 |
| `2` | **판정이 「아니오」** — `ship verdict` NO-GO · `doctor` 진단 실패 · `gate verify` 드리프트 · `evidence check` 미달 |

0 이 아니면 여전히 `cmd || exit 1` 이 걸리므로 **기존 스크립트는 그대로 동작한다** — 바뀌는 것은
둘을 구분할 수 있게 된 것뿐이다. 규약을 `harness --help` 꼬리와 **4개 README** 에 적었다.

### 재측정

`ship verdict` NO-GO → **2** · `gate verify` 미승인 → **2** · 하위명령 오타 → **1** ·
`.harness/` 없는 곳 → **1** · 정상 `status`/`doctor` → **0**.

## ⑥ G12 — [SHIP-01] 되돌아갈 수 있는 유일한 버전이 치명 우회를 갖고 있었다

### 근본 원인

태그가 `v0.1.0` 하나뿐이고 `0.1.1`·`0.1.2` 는 CHANGELOG 에만 있었다. 그런데 `0.1.2` 가 고친 것이
**SEC-300** — 저널에 위조 `gate-approved` 를 꽂아 사람 승인 없이 `npm publish` 를 여는 우회다.
즉 **롤백 = 그 우회를 되살리는 것**이었다.

### 무엇을 어떻게 고쳤나

CHANGELOG 가 선언한 릴리스에 맞춰 주석 태그를 잘랐다:
`v0.1.1` → `9f05b62` · `v0.1.2` → `e79a9c6`(SEC-300 을 고치면서 0.1.2 로 올린 커밋).

### 재측정

`git show v0.1.2:core/src/bashwrite.ts | grep -c SEC-300` → **2**(수정 있음)
`git show v0.1.0:core/src/bashwrite.ts | grep -c SEC-300` → **0**(수정 없음)

**치명 우회 없는 롤백 대상이 생겼다.** 다만 태그는 **로컬**이다 — `git push --tags` 는
바깥으로 나가는 행위라 사용자의 몫으로 둔다.

## ② G4 — [API-04] 훅이 상한에서 10초 예산을 넘겼다 (상한을 실측으로 재역산)

### 근본 원인 — 상한이 **낡은 실측에서 역산**돼 있었다

`MAX_BYTES` 는 훅 타임아웃에서 역산한 값이고, 그 근거는 주석에 「실측으로 판정 비용은 1MB 당
약 1초」라고 적혀 있었다. **규칙이 늘면서 그 전제가 사실이 아니게 됐다.** 감사가 1.03MB 명령에서
10.1~12.8초(3회)를 실측했다 — 즉 4MB 상한 아래 구간이 통째로 **fail-open**(타임아웃 → 무판정 →
통과)이었다. 상한이 「거부」로 보이지만 실제로는 통과를 만드는 구간이 있었던 것이다.

### 부하 창에서 재도 되는 이유

이건 **상한(ceiling) 검사**다. 부하는 시간을 늘리기만 하므로 **부하에서 통과하면 유휴에서도
통과한다** — 결론이 뒤집히지 않는 방향이다. (G7 의 「폴백이 더하는 지연」은 두 값의 **차**라
부하가 양쪽으로 움직여 이 논리가 통하지 않는다. 그래서 G7 만 유휴 창을 기다린다.)

### 실측 (`evidence/api04-cap.md`, 가장 비싼 형태 `cd … > …` 반복, 각 3회 최소값)

| 페이로드 | e2e | 10초 대비 여유 |
|---|---|---|
| 0.26MB | 1.3s | 7.6배 |
| 0.53MB | 2.4s | 4.2배 |
| **1.09MB** | **4.4s** | **2.3배** |
| 2.23MB | 8.0s | 1.2배 ← 예산에 붙는다 |
| 4.68MB | 0.1s | (상한 초과 — 즉시 거부, fail-closed 확인) |

**1MB 를 고른다**: 원 역산이 쓴 기준(여유 ~2.5배)을 **부하 창에서도** 지키는 가장 큰 값이다.

### 이번엔 안 낡게 만든다

숫자를 주석에 적어 두는 것만으로는 또 낡는다 — **이 결함이 그 증거다.** 그래서 회귀 테스트가
**상한에서의 e2e 를 매번 다시 잰다**(문턱: 예산의 80%). 상한 초과가 즉시 거부되는 것도 함께 고정했다.

또한 라운드 2 중 **벤치가 내 자기 회귀를 잡았다** — 자기해제 가드가 `commandLines` 를 3회 돌려
`cd-redirect` 가 1310ms(문턱 1000)를 넘겼다. 한 칸 캐시로 **375ms**(PERF-04).

## ⑤ G10 — [LOGIC-02] 잔여: 웨이브 지시서 (세 번째 길)

### 왜 「막을지 광고를 바꿀지」가 성급했나

처음에 이걸 **사용자 결정 사항**으로 넘겼다: 에이전트가 `Write` 로 활성 웨이브 지시서를 덮을 수
있는데, 막으려면 README 의 「`.harness/` 아래는 언제나 쓸 수 있다」를 함께 고쳐야 하니까.

그건 이분법이었다. **세 번째 길**이 있다 — **쓰기를 막지 않고 손실을 관측 가능하게** 만드는 것.

### 무엇을 어떻게 고쳤나

`doctor` 가 활성 웨이브 지시서를 **부재만** 봤다(파일이 있으면 통과). 그래서 가장 조용한 데이터
손실 경로가 진단의 사각이었다. **있는데 깨진** 경우를 issue 로 올린다 — 처방은 부재와 같아서
(`--repair` 로 activeWave 정산) **기존 복구 경로를 그대로 쓴다.**

광고는 건드리지 않았다. 정상 상태에서 과보고가 없음을 테스트로 고정했다.

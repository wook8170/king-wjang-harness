### 🔴 문제 1 — 축 간 정면 모순 (DEP-11 이 틀렸을 가능성이 높다)

| | 주장 | 근거등급 |
|---|---|---|
| **DEP-11**(축⑦, **verified**) | 플러그인 설치는 `npm install` 을 **트리거하지 않는다** → devDependency 가 설치자 머신에 안 내려온다 | `code`(plugin.json 에 lifecycle 훅 없음을 읽고 추론) |
| **SHIP-04**(축⑩, open MED) | `claude plugin install` 이 플러그인 캐시에서 **`npm ci --ignore-scripts`** 를 돈다 — 설치 후 캐시 **72MB(node_modules 68MB / 73 패키지)** | `measured`(npm debug 로그의 `verbose cwd …/.claude/plugins/cache/…/0.1.2`, 오프라인 대조까지) |

**실측이 코드 독해를 이긴다.** DEP-11 의 추론 오류는 명확하다 — `npm ci` 를 도는 주체는
**Claude Code 플러그인 설치기**이지 패키지의 lifecycle 훅이 아니다. 「lifecycle 훅이 없다」는
「npm 이 안 돈다」를 뜻하지 않는다.

**파급이 G9 까지 간다.** G9(공급망)는 「프로덕션 도달 critical/high = 0」으로 **충족** 판정했고,
그 근거의 한 축이 DEP-06/DEP-11 의 **「devDependency 는 설치자 머신에 안 내려온다」**였다.
그게 틀렸다면 `npm audit` 의 **critical 1 · high 1**(vitest→vite→esbuild 사슬)이 **사용자 머신에
실제로 내려온다.** 「디스크에 있는 것과 실행 경로에 있는 것은 다르다」는 반론이 가능하지만,
**그 반론은 다시 실측으로 세워야 하고 지금 리포트는 그렇게 적혀 있지 않다.**

### 🔴 문제 2 — SHIP-02 가 G3 의 판정선과 충돌

- **G3 목표(착수 전 확정)**: 「광고↔실물 **불일치 0**」 → 현재 **충족**으로 적혀 있다.
- **SHIP-02(open MED, measured)**: README 명령표는 `harness …` 로 쓰여 있는데 **문서대로 설치한
  깨끗한 HOME 에서 `command -v harness` 가 NOT on PATH**.

이건 정의상 **광고↔실물 불일치**다. 축①은 명령 표면을 `node bin/harness --help` 로 확인했지
**문서에 적힌 설치 경로를 밟아 보지 않았다** — 축⑩이 밟아 보고 찾았다. G3 충족은 축①의 범위
안에서만 참이다.

**결과를 보고 게이트를 낮추는 것은 금지**(Iron Rule 1)이므로, 선택지는 둘뿐이다:
① SHIP-02 를 고친다 ② G3 를 **미달**로 되돌리고 판정을 **조건부 출하 가능**으로 내린다.

### 🟡 문제 3 — 장부 위생 (사용자 질문의 표면적 이유)

GO 는 「잔여는 **전부 출하 후 백로그**」를 요구하는데, 37건이 `open` 으로 남아 있다.
백로그라면 `deferred` + **언제·왜 미루는지**가 붙어야 한다(스킬 규정). 지금은 그 구분이 없어서

### 다음 즉시 할 일 (이 순서로)

1. **DEP-11 재검증** — `claude plugin install` 이 실제로 `npm ci` 를 도는지 깨끗한 HOME 에서
   재현. 사실이면 **DEP-11 을 `rejected`(감사 오류)로 바꾸고** DEP-06/G9 의 근거 문장을 고친다.
   그 다음 **「내려온 devDep 이 실행 경로에 있는가」를 실측**해 G9 을 다시 판정한다.
2. **SHIP-02 처리** — 문서대로 설치했을 때의 **정확한 호출 방법**을 확인해 README 명령표를

3. **판정 재산정** — 위 둘의 결과에 따라 GO 유지 여부 결정. **지금은 GO 를 유지하지 마라.**

   처리」로 명시한다. 그래야 대장만 보고도 판정이 읽힌다.
5. push 는 위가 정리된 뒤에. CHANGELOG 계약 변경 2건도 아직 미기재.

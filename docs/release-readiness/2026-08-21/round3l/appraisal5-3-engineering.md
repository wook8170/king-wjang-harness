`${rel}\0` 접두가 경계를 만들어** 서로 달라진다 → 길이 구분자를 **전혀 검증하지 않는다**. 손으로 확인:
길이 제거 시 두 케이스 모두 여전히 differ(true). 즉 테스트가 「규칙」이 아니라 「그 입력쌍의 구멍」을
고정했다(철칙 #4). 게다가 길이 구분자 제거로 **실제 정책 드리프트 충돌**이 열림을 구성해 확인:
`A="P", B="Q\0<Bpath>\0R"` 와 `A="P\0<Bpath>\0Q", B="R"` 가 **같은 해시**(내용 다른 두 정책셋 →
`policyHash` 드리프트 탐지 무력화). 파일에 NUL 바이트가 필요해 실전 악용도는 낮으나, 통합의 핵심
불변식이 무테스트로 남았다.

## 구현자 주장 검증 (한 벌로 모았다 · 추출 실패를 잡는다 · 자동 검사 가능)

1. **「중복 규칙을 한 벌로 모았다 + 드리프트를 구조로 막는 테스트」 → 부분적으로 거짓.**
   해시·`runsCommand`·POLICY_FILES 는 실제로 한 벌이고 잘 테스트됨. 그러나 셸 목록은 소비자
   2/3 만 정본 사용 — `scanBashWrites` 쓰기추출이 세 번째 사본(결함 1). 「구조로 막는」 ENG-199
   테스트는 리스트를 스스로 순회해 빼기 드리프트를 못 잡고 세 번째 사본을 안 본다. 해시 통합의
   가드(ENG-186)는 핵심 불변식(길이 구분자)을 고정하지 못함(MUT1 생존).

2. **「추출 실패를 잡는다(targetLost·copiesHarnessProgram)」 → 보편적으로는 거짓.**
   SEC-207 `targetLost` 는 **`EXPANSION_META`($()·백틱·중괄호·글롭)가 있고 owned-basename 이
   보일 때만** 발화(hook.ts:964-974). 관련 테스트는 통과. 그러나 fish 래퍼의 추출 실패는 확장
   메타가 없고 대상이 owned-basename 도 아니라(`cp /tmp/e src`) `targetLost` 가 **발화하지 않는다**
   → 결함 1 이 그대로 통과. `copiesHarnessProgram` 은 하네스 프로그램 파일 복사만 봄, 일반 소스는 무관.

3. **「자동 검사 가능(bench exit 1)」 → 기계적으로 참, 그러나 잡음에 약함.**
   `GATE_MS=-1`·`BUSY=false` 강제 시 gated shape 초과 → `process.exitCode=1` **확인**(정상은 exit 0).
   그러나 게이트 신호(실측 폴백 ~29ms)보다 **관측 잡음이 큼**: 동일 머신 3연속에서 realistic 폴백
   델타 **+215.6 / +177.2 / +49.7 ms**, corrupt **+63.4 / -0.2 / +31.7 ms**. 유휴로 오인될 순간 부하
   스파이크가 degraded 배치만 때리면 **거짓 실패(exit 1)** 도달 가능(방어는 1분 load 의 조잡한 BUSY
   휴리스틱 하나). 탐지 하한: 문턱 50ms ≈ 실신호 1.7배 → 폴백 비용을 대략 2배로 늘리는 회귀만
   안정 검출, 그보다 작은 회귀는 문턱·잡음 아래로 잠긴다. 내 세션 병렬 작업으로 머신 부하가 계속
   높아 **깨끗한 유휴 p95(제품 실값·G9 <150ms 절대치)를 독립 확인하지 못함**(정직 고지).

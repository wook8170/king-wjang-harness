## 개정 1 — 위협 모델을 **에이전트 레인**으로 못 박는다 (2026-08-22, 사용자 결정)

**바꾼 것**: 실효성 조건에서 「저널 위조 후 `doctor` 가 탐지」를 **범위 밖**으로 옮긴다.
그 조건이 요구하는 것은 저널 줄마다 해시 체인을 박아 **사람이 손으로 고친 것**까지 잡는
장치인데, 이 제품의 위협 모델은 그것이 아니다.

**사유**:
- 이 하네스가 막으려는 것은 **에이전트가 스스로 강제를 푸는 것**이다. 에이전트 경로는 훅이
  막는다 — `.harness/events.jsonl` 쓰기는 Write·Bash·접두 명령·디렉토리 대상·스크립트 실행까지
  전부 deny 다([SEC-49]·[SEC-50]·[SEC-90]·[SEC-91]·[SEC-92]).
- **사람은 애초에 `.harness/` 를 통째로 지울 수 있다.** 자기 프로젝트의 로그를 자기가 고치는
  것을 막는 장치는, 막지 못하면서 비용만 무는 쪽에 가깝다. 정책 파일을 사람이 직접 고치는 것을
  **의도된 탈출구**로 남긴 [SEC-69] 의 판단과 같은 선이다.
- 바이브 코더의 편의를 위한 플러그인이라는 제품 성격상, 사용자 자신을 상대로 한 무결성 방어는
  과잉이다.

**그래서 실효성은 이렇게 잰다**: 에이전트의 도구 호출이 (a) 설계 트랙 소스 (b) 코어·정책 파일
(c) `--force`/`--accept-policy` 잠금에 **도달할 수 있는가**. 사람이 터미널에서 직접 하는 것은
결함으로 세지 않는다.

**남는 한계(정직 고지)**: 사람이 저널을 위조하면 `doctor` 는 알아채지 못한다. 이것은 닫힌
것이 아니라 **범위 밖으로 둔 것**이며, 출하 리포트의 「알려진 한계」에 그대로 적는다.

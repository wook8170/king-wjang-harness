## [PERF-26] MED — fixed → **verified**

**측정** `evidence/latency.log` 「라운드3 재측정」 절. 절차는 원 측정과 동일(저널 10만건 샌드박스,
state.json 제거로 폴백 경로 강제), 보강 2가지 — 통제(정상 경로) 동시 측정 + 정순·역순 반복.

| 계열 | 창 1 p95 | 창 2 p95 | 게이트 |
|---|---|---|---|
| 정상 경로(통제) | 82ms / 65ms | 59ms / 62ms | — (창 위생 검증용) |
| **폴백(state 부재)** | **83ms / 81ms** | **82ms / 101ms** | **< 150ms ✅ (최악 101ms, 여유 33%)** |

**조건 편차와 채택 사유** — 라운드 2 핸드오프는 「1분 load < 2」 창을 조건으로 걸었으나
OrbStack·Ollama 상주로 그 창은 오지 않았다(측정 창 load 3.2~11.3). 그럼에도 verified 로 올린
근거는 latency.log 에 상세 기록했다: ① 핸드오프가 명시한 창 무효 징후(통제 팽창·순서 역전)
미발생, ② G9 는 상한 게이트라 경합은 수치를 부풀릴 뿐 — 오염 가능 창에서의 통과는 조용한
창에서의 통과를 함의(a fortiori), ③ 독립 2창 재현. **게이트 임계값 150ms 는 변경하지 않았다** —
바꾼 것은 측정 위생 전제조건이며, 사실·시각·사유를 남긴다(스킬 규정).

**파생 효과** — **G9 초록.** 단, **종합 판정 승격은 보류한다** — 같은 시각 피어 세션이
라운드 2의 USE-59(생성 문서 i18n) `verified` 가 부분 스윕에 근거한 **과다 주장**이었음을
발견했고(잔여 한국어: adr 렌더·doctor/gate/profile 진단·wave 예외·mcp description·migrate
안내·usage 티어 지침·generic.json), 정정 행 반영을 진행 중이다(Iron Rule 7 — 감사도 틀린다).
판정 갱신은 라운드 3 본편이 대장에 정정을 실은 뒤에 한다. 게이트 전건 집계(13/13)도 그때

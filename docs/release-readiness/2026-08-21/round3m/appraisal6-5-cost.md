## 반대 방향 — 비용 절감이 방어를 빼먹는 곳 (그리고 모범 사례)

### 모범 사례 (비용 캡을 두되 「안 본 것 = 통과」로 만들지 않았다)
이 리포는 다운스트림 비용 캡을 **전부 fail-closed** 로 고쳤다 — 본받을 태도다:
- `SCRIPT_MAX_BYTES`(64KB) 초과 스크립트 → `unread` 로 올려 **DENY**(SEC-B3). 「못 봤으니 통과」→「못 봤으니 말한다」.
- `SCRIPT_MAX_DEPTH`(3겹) 초과 사슬 → `tooDeep` 로 올려 **DENY**(SEC-175).
- 루트 밖 스크립트 → 전 규칙 대신 **소유 파일만 좁게** 보되 건너뛰지 않음(SEC-219).
- read-only Bash 활동 제외 → 스캐너가 「모르겠다」면 **활동으로 센다**(COST-111, fail-closed).
- `expandBraces` cap 64 로 폭발 방지(SEC-207).

### 빠진 곳 — **정문(명령 문자열) 자체엔 상한이 없고, 그 파서가 2차다**
다운스트림은 전부 캡을 걸었는데 **가장 앞의 명령 파싱 진입점엔 길이 캡이 없다**(`grep` 결과: `rawCmd`/`cmd` 에 length 가드 0건). 그래서 큰 명령 하나로 「너무 커서 시간이 다 갔다」가 실제로 **통과**가 된다:
- 30KB 변형 명령 → 훅 wall-time **1.2초**(e2e). 외삽 시 **~90–100KB 에서 10초 `hooks.json` 타임아웃 초과** → 훅이 죽고 판정이 사라진다 = **fail-open**(그 도구 호출은 deny 되지 않는다).
- 즉 위반 쓰기를 담은 큰 명령을 no-slash 토큰으로 패딩하면, 다운스트림 fail-closed 캡들을 **파서가 완주하기 전에** 타임아웃으로 무력화할 수 있다.

### 더 나쁜 것 — **프로젝트 자체 벤치가 이 경로를 못 본다**
`scripts/bench-hook-latency.mjs:33` 의 `PAYLOAD` 는 `command: 'ls'` 로 **고정**이고, 벤치는 저널 `SHAPES` 만 바꾼다. 이번 라운드가 실제로 바꾼 **명령 파싱 뜨거운 경로**(따옴표 인식 분해·`pathLikeMentions`)는 벤치가 **한 번도 실행하지 않는다.** G9 게이트는 저널 재생 회귀만 잡고, 결함 #1·#2 는 CI 에서 영영 안 보인다.

## 찾은 결함

### #1 [COST · MEDIUM] `pathLikeMentions` O(n²) — 매 변형 명령마다·상한 없이·타임아웃 fail-open
- **파일:줄**: `core/src/bashwrite.ts:959` 정규식 `/[A-Za-z0-9_.\-]*\/[A-Za-z0-9_.\-\/]+/g`. 탐욕 `[...]*` 뒤 필수 `/` → 긴 no-slash 런에서 시작 위치마다 전체를 소비·백트래킹 = **O(n²)**.
- **호출 경로**: `hook.ts:1447 copiesHarnessProgram` → `hook.ts:969 pathLikeMentions(cmd)` 를 **모든 변형 Bash 명령에서 무조건** 실행(+ `hook.ts:1440` 안전망).
- **실측(인프로세스, 부하)**: 2KB=2.6ms · 10KB=**138ms** · 50KB=**3495ms** (5배 입력마다 ~25배 = 5²). 100KB/200KB 는 120초 내 미완.
- **실측(커밋 dist e2e, 부하)**: `cp x y; echo <30KB no-slash>` → 훅 **1223ms**. 외삽 ~100KB → >10s 타임아웃.
- **재현**:
  ```
  SB=$(mktemp -d); ( cd "$SB" && harness init )
  BODY=$(printf 'a%.0s' {1..30000})
  echo "{\"tool_name\":\"Bash\",\"tool_input\":{\"command\":\"cp x y; echo $BODY\"}}" \
    | CLAUDE_PROJECT_DIR=$SB harness-hook pre-tool   # → 1초+ (유휴), no-slash 길이에 2차
  ```
- **영향**: 큰 명령 하나로 훅 지연 초 단위 → 10초 타임아웃 시 강제가 조용히 열린다. 정상 입력엔 무해(짧음)하나 상한이 없어 상계가 사람이 기다리는 최대 지연이 된다 — [COST-A] 주석이 경고한 바로 그 실패 양식이 다른 함수에 재현.
- **처방 방향**: 명령 길이 캡(예: N KB 초과 시 판정 보류→명시 처리) + 정규식을 백트래킹 없는 형태로(`[^/\s]` 런을 앵커드 스캔). 다운스트림 캡과 **같은 fail-closed 태도**를 정문에도.

### #2 [COST · LOW] `cwdAt` O(R·S) — 많은 `cd…>` 세그먼트에서 2차
- **파일:줄**: `core/src/bashwrite.ts:173 cwdAt` 가 리다이렉트마다 전 세그먼트를 재순회(`bashwrite.ts:582` 루프). R 리다이렉트 × S 세그먼트 = O(R·S).
- **실측(인프로세스, 부하)**: 512 segs(10.5KB)=21.7ms · 768 segs=67ms (세그먼트 2배마다 x3.9 = 2차).
- **영향**: #1 보다 덜 심각 — 수천 개 `cd x > f ; …` 는 비자연적 입력. 상한 없음은 동일.
- **처방 방향**: 세그먼트 cwd 를 선계산 후 리다이렉트 위치를 이진탐색, 또는 세그먼트 경계로 리다이렉트를 사전 버킷팅.

### #3 [COST · MEDIUM · 감정 대상 벤치] `bench:hook` 이 바뀐 뜨거운 경로를 안 잰다
- **파일:줄**: `scripts/bench-hook-latency.mjs:33` `PAYLOAD = {command:'ls'}` 고정 · `SHAPES`(36–39)는 저널만 변주.
- **영향**: 이번 라운드가 바꾼 명령 파싱 경로(따옴표 분해·`pathLikeMentions`)를 벤치가 **전혀 실행하지 않아** #1·#2 회귀가 G9 게이트에 안 걸린다. 광고 재현 절차([PROD-180])의 사각.
- **처방 방향**: `PAYLOAD` 에 명령 길이/부류 축(긴 no-slash·따옴표 다수·`cd`-리다이렉트 다수)을 추가하고 명령-파싱 델타에도 게이트를.

## 못 잰 것 (정직 고지)

1. **유휴 절대값** — load 14–17 을 못 낮춰(kill 차단) **유휴 wall-time 을 한 번도 못 쟀다.** 「폴백 p95 < 150ms 절대」 확증 불가. 유휴면 통과가 유력하나(node 바닥값만 25–30ms 추정, 델타≈0) **측정으로 확정 못 함.**
2. **Claude Code 타임아웃 시맨틱** — 10초 초과 시 CC 가 훅을 죽이고 그 도구 호출을 **allow 로 진행**한다는 것은 `hooks.json timeout:10` 과 훅의 무해 계약으로 **추론**했을 뿐, CC 의 kill→allow 동작을 직접 관측하진 못했다. 파서가 초 단위·>10s 에 도달함은 실측.
3. **100KB+ 명령 절대 e2e** — 120초 내 미완이라 30KB 까지만 e2e, 그 이상은 인프로세스 외삽.
4. **세션-start/stop 훅 지연** — pre-tool 만 집중 측정. session-start(웨이브 발췌·nonce·i18n)와 stop 가드의 wall-time 은 미측정.
5. **부하 격리** — 인프로세스 비율은 부하에 강하나, 절대 µs/op 자체는 경쟁으로 부풀어 있다(판정엔 비율만 사용).

## 점수 산출 근거

- **+ (강점, measured)**: 비간섭 sh 게이트 4.4ms(vs 106.8ms) 감축 실측 · 저널 재생 폴백 델타≈0·G9 통과 · 벤치의 BUSY 가드·node 바닥값 분리 표기가 정직 · 정상 입력(따옴표·중첩·긴 명령)은 **선형** · 다운스트림 비용 캡을 전부 fail-closed 로 고친 모범.
- **− (감점)**: 이번 라운드가 넓힌 파서 뜨거운 경로에 **상한 없는 O(n²)**(#1, MEDIUM) — 큰 명령에서 초 단위·타임아웃 fail-open · `cd`-리다이렉트 2차(#2, LOW) · **프로젝트 자체 벤치가 그 경로를 못 봐**(#3, MEDIUM) 회귀가 CI 에 안 걸림.
- **4.8 아님**: 루브릭 4.8 은 「조건 전건 충족 + 잔여 LOW 이하」. 폴백·비간섭·감축 조건은 (부하 한계 내에서) 충족하나, **fail-open 결과를 갖는 MEDIUM 비용 결함이 열려 있고** 자체 게이트가 그것을 못 본다 → 잔여가 LOW 이하가 아니다.
- **3.5 이상인 이유**: 정상-케이스 비용은 잘 통제되고 헤드라인 최적화(비간섭·폴백)가 실재·측정됨. 결함은 큰·적대적 입력에 국한.
- **최종 4.0** — 루브릭 현재값과 동일. 「좋은 가성비 + 정문에 상한 없는 2차 구멍 하나」.

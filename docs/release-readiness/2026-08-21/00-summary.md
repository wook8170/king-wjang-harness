**남은 조건 ①** — [PERF-26] 열화 경로 지연의 **절대 p95 < 150ms 재측정**. (라운드 2에서도 미해결)
기제(상태 무변이 이벤트 미파싱)는 단위 테스트로 확인했으나, 라운드 1·2 두 세션 모두 머신 load 가

**누가·무엇을**: 조용한 창(load < 2)에서 `evidence/latency.log` 의 절차를 그대로 재실행 →
p95 < 150ms 확인 → 대장 PERF-26 을 `fixed` → `verified` 로 올린다.

## 착수 시점 판정 원문 — 출하 불가 (NO-GO)

**차단 결함 2건.** 둘 다 같은 뿌리에서 나온다 — **훅이 Bash 표면에서 파일 쓰기를 보지 않는다.**

- **[SEC-50]** 설계 트랙 소스 쓰기 금지가 `echo "x" > src/app.ts` 한 줄로 풀린다.
  `Write` 는 deny 하면서 Bash 리다이렉트·heredoc·`touch` 는 통과한다.
- **[SEC-49]** `events.jsonl` 에 이벤트 한 줄을 append 하고 `doctor --repair` 를 부르면
  **페이즈와 게이트가 위조된다** — 사람이 클릭한 적 없는 승인 도장이 찍힌다.

이 제품의 공개된 핵심 약속은 *"AI가 설계 승인 전에 코드를 못 쓰게 **물리적으로** 막습니다 —
지침이 아니라 훅으로"* 다. MCP 어댑터는 그 약속을 지키려고 코드 수준 불변식까지 동원했고
(`core/src/mcp.ts:294`, 실측으로 뚫리지 않음을 확인 — [SEC-33]), 경로 우회·심링크·프롬프트
인젝션 방어는 이 범주에서 드물게 진지하다. **그런데 검사되지 않는 Bash 두 줄이 그 전부를
우회한다.** 잠근 문이 훌륭한 것과 옆에 열린 창이 있는 것은 별개다.

**나머지는 대체로 단단하다.** 584 테스트 3회 동일 · tsc 0 · 빌드 바이트 재현 · 맨 클론 설치 ·
롤백 리허설 · 이력 비밀 0 · 프로덕션 취약점 0. 차단 2건은 **국소적이고 수정 경로가 분명하다**
(⑥ 「완화 방향」). 이건 「기반이 부실하다」가 아니라 **「한 표면을 안 막았다」**다.

**착수 시점에 적은 조건 3건은 전부 닫혔다** — `--help` 구현(G11 ✅) · doctor 정합성 회복(G12 ✅) ·
미구현 명령 2건 구현(①축 ✅). 근거는 `evidence/round1-verify.log`.

# 이 감사에서 배운 것

1. **정적 감사·소스 전량 열람으로도 안 보이는 결함이 있다.** 감정서는 코어 11모듈을 전부 읽고
   「경로 우회를 진지하게 막았다」고 평가했다. 사실이다 — `Write` 표면에서는. **막힌 다음에
   무엇을 시도하게 되는지**를 실제로 해 봐야 옆문이 보인다.
2. **측정 도구가 결함을 지어낸다.** zsh 는 무인용 확장을 단어 분리하지 않는다 — 이 한 가지로
   「미구현 명령 48건」이라는 가짜 결함이 나왔다. 실측 결과가 너무 극적이면 도구부터 의심하라.
3. **상시 빨간 진단은 위조를 숨긴다.** [OPS-20](doctor 상시 오탐)이 없었다면 [SEC-49] 의 저널
   위조가 `doctor` 의 `ok:false` 로 드러났을 것이다. 오탐 하나가 진짜 경보를 무의미하게 만든다 —
   Iron Rule 6 이 테스트뿐 아니라 **운영 도구에도** 적용된다.
4. **같은 규율의 부분 적용이 결함의 뿌리다.** 시각 주입(`usage`·`migrate`·`tokens` 에는 있고
   `gate` 에는 없음 → [OPS-20]), 하위명령 안내(절반만 → [API-27]), 인젝션 방어(두 벌 → [SEC-28]),
   코어 파일 보호(Write 만 → [SEC-51]). **네 결함이 전부 같은 모양이다.**

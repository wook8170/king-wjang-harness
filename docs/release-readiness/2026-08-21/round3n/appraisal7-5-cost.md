## [COST-228]·[SEC-233] 재검증

### [COST-228] `pathLikeMentions` — **봉인 확인 (fail-open 제거됨)**
직전 라운드가 낸 O(n²)(탐욕 접두 `[A-Za-z0-9_.\-]*\/…` 의 백트래킹)는 슬래시를 먼저 찾고 뒤로 걷는 형태로 교체됐다(`bashwrite.ts:1048`). **재현으로 확인**:
- 인프로세스(HEAD 앵커) noslash: k2 0.20 · k8 0.26 · k32 0.98 · k64 1.94 · k128 3.91ms — **더블링마다 ~x2 = 선형**. 직전 라운드의 50KB 3495ms 가 사라졌다.
- e2e(커밋 dist) noslash: 2KB 69.3 · 10KB 76.2 · 30KB 91.6 · 50KB 116.2 · **200KB 226.6ms(p95)** — 선형. 외삽해도 200KB에서 10초 타임아웃 근처도 안 간다.
- **결론**: 헤드라인 fail-open 은 진짜로 닫혔다. 이 라운드의 최대 개선.

### [SEC-233] 큰 페이로드 stdin — **fail-closed 확인**
| 입력 | 관측(hook-only wall) | 판정 |
|---|---|---|
| 33MB 페이로드(32MB 상한 초과) | **0.07s** | **deny**(unread → 거부) ✓ |
| `/dev/zero`(끝없는 입력) | **0.08s** | **deny**(MAX_BYTES 상한) ✓ |
| 닫히지 않는 파이프(위반 뒤 8초 유지) | **3.03s**(DRAIN_MS 2s + 판정) | **deny** ✓ |
| 8MB 정상 페이로드 | 8.6s | 완주(판정 도달) |
| 12MB 정상 페이로드 | **12.9s** | 완주하나 **>10s** — 실 CC 라면 kill→fail-open |

- 상한(32MB)·끝없는 입력은 **빠르게 거부**한다 — 「못 읽으면 통과」가 아니라 「못 읽으면 거부」. 드레인 경로 자체의 비용은 상한(2s)이 있다. **큰 페이로드에서 판정이 끝난다**(멈추지 않음).
- **잔틈(LOW)**: 10–32MB 구간 정상 페이로드는 상한 안이라 끝까지 읽고 판정하는데, 12MB에서 e2e 12.9s > 10초 훅 타임아웃. 다만 **12MB짜리 단일 Bash 명령은 자연 입력이 아니다**(비현실적). 결함 등재하되 LOW.

## 발견 결함

### #1 [COST · MED] `cwdAt` O(R·S) 2차 — e2e 8KB에서 10초 타임아웃 초과 (fail-open, 단 위반 은닉은 아님)
- **파일:줄**: `bashwrite.ts:173 cwdAt` 가 리다이렉트마다 전 세그먼트를 재순회(`bashwrite.ts:666` `resolveIn(cwdAt(segs, r.index), …)`). R 리다이렉트 × S 세그먼트 = **O(R·S)**, 그리고 `cd x` 반복이 cwd 문자열을 O(n)으로 키워 상수가 크다.
- **실측(인프로세스, HEAD 앵커)** `cd x > f` × N: k4 4.40 · k8 14.70 · k16 56.67 · **k32 224.06ms** — 더블링마다 **~x3.9 = 2차**.
- **실측(커밋 dist e2e)** `cd x > f ; …`: 1KB 284 · 2KB 913 · 4KB 3640 · **8KB 15180ms**(단발). 더블링마다 ~x4. **~8KB(약 819 세그먼트)에서 이미 15초 → 10초 훅 타임아웃 초과.**
- **재현**:
  ```
  SB=$(mktemp -d); ( cd "$SB" && harness init )
  node -e 'process.stdout.write(JSON.stringify({tool_name:"Bash",tool_input:{command:Array.from({length:819},()=>"cd x > f").join(" ; ")}}))' \
    | CLAUDE_PROJECT_DIR=$SB harness-hook pre-tool   # → 약 15초
  ```
- **왜 결함인가**: 상한 없는 2차라 상계가 사람이 기다리는 최대 지연이 된다. 8KB짜리(작다) `cd`-리다이렉트 명령 하나로 훅이 15초 멈추고, 실 CC(`hooks.json` timeout:10)에서는 kill → **fail-open**. 직전 라운드가 LOW(#2)로 본 바로 그 경로가, **e2e로 재니 훨씬 작은 입력에서 타임아웃에 닿는다**.
- **은닉 불가 재현으로 격하**: 위반을 이 패딩으로 숨겨 통과시키려 했으나 **재현 실패** — (a) deny 는 조기 단락되어 위반이 앞에 있으면 102ms에 deny, (b) 타임아웃을 넘기는 유일한 입력(`cd x`가 끝없이 깊어짐)은 뒤따르는 리다이렉트가 **깊은 비보호 경로**로 해석돼 참 판정이 애초에 allow(셸 의미론과 일치), (c) cwd를 루트로 되돌리는 패딩(`cd a>f;cd ..>f`)은 경로 문자열이 짧아 **빠르고**(8KB 84ms) 뒤 위반을 정상 deny. **즉 보안 우회가 아니라 지연/DoS.** 그래서 MED(타임아웃-fail-open 지연) — 단, 판정 은닉은 없음을 명시.
- **처방 방향**: 세그먼트 cwd 를 선계산 후 리다이렉트 위치를 이진탐색(또는 사전 버킷팅). 명령 길이/세그먼트 수 캡 + 다운스트림과 같은 fail-closed 태도.

### #2 [COST · MED · 감정 대상 벤치] `bench:hook` 이 명령 파싱 뜨거운 경로를 **여전히** 안 잰다
- **파일:줄**: `scripts/bench-hook-latency.mjs:33` `PAYLOAD = {command:'ls'}` **고정**(직전 라운드 지적 후 무변). `SHAPES`(36–42)는 저널만 변주.
- **왜 결함인가**: G9 게이트는 저널 재생 회귀만 잡는다. 이번 라운드가 바꾼(그리고 #1이 실재하는) **명령 파싱 경로**(scanBashWrites·`cwdAt`·pathLikeMentions·따옴표 분해)를 벤치가 **한 번도 실행하지 않아**, #1의 15초 2차가 CI에 영영 안 걸린다. 광고 재현 절차([PROD-180])의 사각이 그대로 남았다.
- **처방 방향**: `PAYLOAD` 에 명령 부류 축(긴 no-slash·`cd`-리다이렉트 다수·따옴표 다수)을 추가하고 명령-파싱 델타에도 게이트를.

### #3 [COST · LOW] 10–32MB 정상 페이로드는 완주하나 e2e >10초
- **파일:줄**: `cli.ts readAllStdin` `MAX_BYTES = 32MB`. 32MB 미만은 끝까지 읽고 판정 → 12MB에서 e2e 12.9s > 타임아웃.
- **왜 결함인가**: 상한(32MB)과 「빠른 정상」 사이 구간이 타임아웃을 넘길 수 있다. 다만 12MB 단일 Bash 명령은 비자연 입력이라 LOW. (상한 자체는 옳게 fail-closed.)
- **처방 방향**: 판정 가능 상한을 훅 타임아웃에서 역산한 값(예: 수 MB)으로 낮추고 초과 시 명시 거부.

## 직전 라운드 대비 (3-M 4.0 → 4.3)

| 항목 | 3-M | 3-N (이번) |
|---|---|---|
| `pathLikeMentions` O(n²) fail-open (#1, MED) | **열림** — 헤드라인 결함 | **[COST-228]로 봉인, 재현 확인** — noslash e2e 선형, 200KB 226ms |
| `cwdAt`/cd-redirect 2차 (#2, LOW→MED) | LOW(인프로세스만 봄, 작아 보임) | **e2e로 재니 8KB→15초 > 타임아웃**. 단 **보안 우회 재현 실패**(은닉 불가) → 지연/DoS MED |
| 벤치가 파서 경로 못 봄 (#3, MED) | 열림 | **여전히 열림**(PAYLOAD `ls` 고정 무변) |
| 비간섭·폴백·세션 컨텍스트 | 측정(부하 오염) | **재측정, 부하 4.0 미만에서 확증** — 4ms · 델타<50ms 양표면 · ~236토큰 |
| 측정 부하 | **14–17**(고아 `yes` 10개, 유휴 도달 불가) | **2.8**(문턱 미만) — 절대값도 신뢰 가능 |

**핵심 변화**: 가장 심각한(자연 도달성 있고 fail-open) 결함이 실제로 고쳐졌고 내가 재현으로 확인했다. 남은 것은 (a) **비자연 입력에만** 걸리고 **우회는 불가능한** cd-redirect 2차와 (b) 그것을 볼 눈이 게이트에 없다는 점. 그래서 4.0 → **4.3** 반보 상향이 정당하다. **4.8은 아니다** — 잔여에 MED 두 건(#1 타임아웃-지연, #2 게이트 사각)이 있어 「LOW 이하」가 아니다.

**가성비 총평**: 이 도구가 무는 비용은 정상 사용에서 **극히 낮다** — 비간섭 4ms, 하네스 프로젝트에서 도구 호출당 ~63ms(그중 36ms가 node 기동, 제품 몫은 ~27ms), 세션당 ~236토큰, 폴백조차 +25ms 미만. 주는 것(에이전트 자기-탈출 차단·저널 감사·페이즈 규율)에 비해 **정상 경로 비율로는 켤 만하다.** 감점은 전부 **비자연·적대적 입력의 꼬리**에 몰려 있고, 그중 최악(fail-open 은닉)은 이번에 닫혔다.

## [USE-59] HIGH — 생성 문서 5종이 한국어 전용

예외 메시지는 라운드 1에서 전량 끝났고, 남은 것은 **렌더 문서**였다.

| 모듈 | 생성 문서 |
|---|---|
| `report.ts` | 게이트 리뷰 패킷 · 요구사항 추적 매트릭스(RTM) · 프로젝트 허브 |
| `ship.ts` | 결함 대장(`readiness.md`) · 릴리스 체크리스트 · 출하 판정 사유 |
| `loop.ts` | 웨이브 실행/검증 브리프 · 크리티컬 소환문 · 루프 판정 사유 |
| `evidence.ts` | Playwright 시나리오 · P9 비교 리뷰 패킷 |
| `design.ts` | 디자인 시스템 정본 HTML |

### 어떻게 고쳤나

예외 메시지의 `tr(root, {en, ko})` 를 렌더 문서에 그대로 쓰면 **줄마다 config 를 다시 읽는다**.
그래서 언어를 진입점에서 한 번만 해석해 함수로 넘긴다:

```ts
type Tr = (m: Msg) => string;
const trFor = (lang: Lang): Tr => (m: Msg) => pick(m, lang);
// 진입점: const t = trFor(langFor(root));  → 하위 헬퍼에 t 를 넘긴다
```

세 문서(패킷·RTM·허브)가 공유하는 문장은 모듈 상단 카탈로그(`MSG`)에 모았다 — 같은 문장이
파일 안에서 두 번 번역되면 언젠가 갈린다.

### 측정이 드러낸 「5개 파일 밖」 누수

작업 범위를 파일 5개로 잡았지만, **실제 출력을 재보니 그 밖에서도 새고 있었다.**
소스 grep 이 아니라 CLI 산출물을 측정했기 때문에 잡혔다:

- **`wave.ts`** — 웨이브 지시서 본문 템플릿(`## 목표` / `## 완료 기준` / `## 턴 로그`)과
  `(미지정)` 마일스톤 자리표시자. 자리표시자는 쓰는 쪽(cli·mcp)과 읽는 쪽(파서 폴백)이
  **같은 `UNSPECIFIED` 상수**를 쓰게 통일했다 — 갈리면 저장된 파일과 렌더가 다른 말을 한다.
- **`tokens.ts`** — 생성 파일 배너(`생성물 — 손으로 고치지 마라`). 생성기는 순수(doc → 문자열)라
  root 가 없어, `lang` 을 인자로 받고 호출부(cli·design)가 넘긴다. 결정성은 그대로다
  (같은 doc + 같은 lang → 바이트 동일).
- **비교 패킷·정본 HTML 의 `<html lang="ko">`** 하드코딩 → 실제 언어를 따라간다.

### 재측정 (`evidence/round2-verify.log` §2·§3)

`HARNESS_LANG` 미설정 샌드박스에서 CLI 전 명령을 돌리고 산출물을 전부 훑었다:

- CLI stdout 전량 — 한국어 **0**
- `.harness/` 산출물 전체(웨이브 지시서·결함 대장·상태·저널) — 한국어 **0**
- 생성 토큰 파일(`tokens.css`·`tokens.ts`·`tailwind.tokens.js`) — 각 **0**
- Playwright 사양(`e2e/ux-7.spec.ts`) · 비교 패킷 HTML · 정본 HTML — 각 **0**

`HARNESS_LANG=ko` 회귀도 함께 실측했다 — 한국어 그대로 나온다.
**영문 기본은 기본값 변경이지 한국어 제거가 아니다.**

## [API-57] HIGH — `wave create --acceptance` 가 조용히 무시된다

영문 E2E 를 돌리다 수용 기준이 빈 웨이브가 나와서 잡혔다.

`--help` 는 `create --goal <text> [--milestone <m>] [--refs <ids>] [--acceptance <list>]` 를
광고하는데, 파서는 `flag(args, 'accept')` 만 읽었다. `flag()` 는 `--${name}` **정확 일치**라
`--acceptance` 는 어디에도 걸리지 않는다.

**왜 나쁜가**: 실패하지 않는다. 웨이브가 exit 0 으로 생기고 수용 기준만 비어 있다.
그리고 그 빈 기준은 검증자 브리프에서 「(명시 없음 — 판정 불가다)」로 나타나, 사람은
**자기가 기준을 안 적었다고 믿게 된다.** 도구가 삼킨 것을 사용자 탓으로 돌리는 실패다.

수정: 광고한 이름(`--acceptance`)을 정본으로, `--accept` 는 별칭으로 유지(기존 호출 불파괴).
재측정: 수정 전 `[]` → 후 `['login returns 200']`, `--accept` 도 계속 동작
(`evidence/round2-verify.log` §4). 회귀 테스트 `core/test/cli.test.ts:42`.

## [API-58] MED — `design baseline --png <file>` 가 성립 불가

같은 어긋남의 다른 얼굴. 도움말은 `<UX-x> --png <file>` 인데 파서는 위치 인자 `rest[1]` 만 읽어
**`--png` 라는 문자열 자체를 파일 경로로 삼는다.** 도움말대로 친 호출은 exit 1 로 죽는다.

API-57 과 달리 시끄럽게 실패하므로 심각도는 MED. 수정은 같은 형태 —
`flag(args,'png') ?? rest[1]`. 회귀 테스트 `core/test/cli.test.ts:59`.

## 전수 스윕 — 남은 게 없는지 확인 (`evidence/round2-verify.log` §6)

둘을 우연히 하나씩 찾은 것으로 끝내지 않고, `help.ts` 가 광고하는 플래그 **전체**를
`cli.ts` 파서와 기계 대조했다. 수정 전 2건(`--acceptance`·`--png`), **수정 후 0건.**

### G11 이 놓쳤던 것

`gates.md` 의 **G11 CLI 계약**은 「전 서브커맨드 `--help` exit 0 · 미지 명령 exit≠0 ·
필수 인자 누락 시 침묵 성공 0」을 봤고 라운드 1에서 초록이었다. 하지만 검사가
**명령 수준**이라 **플래그 수준의 광고-구현 어긋남**은 통과했다.
「도움말이 광고한 플래그가 실제로 먹는가」는 별개의 검사이고, 위 스윕이 그 자리를 메운다.

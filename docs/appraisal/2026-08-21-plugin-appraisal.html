종합 판정

"v0 치고는 이례적으로 단단한 기반 — 지금은 엔진이지 상품이 아니다."

세션 단절·설계 무시·미정산 종료라는 에이전트 코딩의 3대 실패 모드를 프롬프트가 아니라 훅으로 차단하는 접근은 시장에서 실제로 드물고, 코드 품질(이벤트 소싱·보안 방어·198 테스트)은 v0 플러그인 기준을 한참 상회한다. 반면 페이즈 게이트가 미구현(phase set 수동)이라 강제력에 자기해제 구멍이 있고, 한국어 전용·의식(ceremony) 비용·발견성 부족이 대중 수용의 벽이다. 장기 프로젝트를 굴리는 소수에게 깊게 팔리는 도구이지, 바이브코더 대중에게 넓게 팔리는 도구는 아직 아니다.

01무엇인가

슬래시 커맨드가 아니라 훅 4종(SessionStart / PreToolUse / PostToolUse / Stop) + CLI다. events.jsonl 저널을 진실의 원천으로 페이즈(P0~P12)·웨이브(작업 지시서)·설계 원장을 관리하고, 훅이 규율을 물리 차단으로 강제한다. 설계 스펙은 13페이즈 풀사이클 SDLC를 그리고 있으나 현재 구현은 코어 엔진 v0 — 상태 머신·웨이브·원장·doctor·훅 판정기까지다.

  • 설계 트랙(P0~P6): 소스 쓰기·배포성 Bash를 deny. 허용은 .harness/·docs/·루트 *.md뿐.
  • 구축 트랙(P7~): 반대로 설계 문서 직접 수정을 deny — backtrack 공식 역행으로만.
  • Stop 가드: 활성 웨이브에 미정산 작업이 있으면 세션 종료를 막고 턴 로그 정산을 요구.
  • 코어 파일 보호: state.json·events.jsonl·ledger.yaml 손편집을 페이즈 무관 차단.
  • UX 증적 게이트: UX 노드를 참조한 웨이브는 스크린샷 증적 없이 완료 불가.

02효용성 — 어떤 아픔을 해결하나 4.5

에이전트 코딩에서 실제로 돈이 새는 지점 세 곳을 정확히 겨냥한다.

실패 모드하네스의 답실증
세션 단절·컨텍스트 소실SessionStart가 페이즈·활성 웨이브·최근 턴 로그를 자동 주입 + Stop 가드가 정산을 강제Moa 프로젝트가 9차례 세션 릴레이로 조건부 출하까지 도달
설계 승인 전 구현 폭주PreToolUse가 설계 트랙에서 Write/Edit 자체를 deny — 모델이 잊어도 물리적으로 막힘E2E 23건에서 deny 실측 (readiness 감사 동봉)
상태 파일 오염·유실저널 우선 변이 순서 계약 + doctor --repair 저널 재생 복구state.json 삭제·손상 시 인메모리 재생으로 판정 지속

핵심 통찰이 좋다: CLAUDE.md 지침은 컨텍스트 요약·모델 변덕에 침식되지만, 훅 deny는 침식되지 않는다. "모델이 규칙을 잊는" 문제를 지침 반복이 아니라 인프라로 푼 것이 이 플러그인의 존재 이유다.

03실효성 — 강제가 정말 강제인가 3.5

잊는 것은 완벽히 막고, 우회하려 드는 것은 v0에서 부분적으로만 막는다.

  • 구멍 1 harness phase set P7 이 v0 임시 명령이라 게이트 없이 페이즈를 넘길 수 있다 — 에이전트가 Bash로 스스로 실행하면 설계 트랙 차단이 풀린다. 스펙에 "게이트 구현 후 대체"로 명기된 알려진 구멍이지만, 현재 강제력의 최대 약점.
  • 구멍 2 Stop 가드는 "사소한 턴이면 사유 한 줄 보고 후 종료 가능"이라 반(半)강제 — 다만 이는 잡음 방지를 위한 의도된 설계다.
  • 막은 것 경로 우회는 진지하게 막았다: 리터럴·realpath 이중 공간 정규화로 심링크·docs/../src 우회를 차단하고, 웨이브 frontmatter·턴 로그 등 신뢰 경계 밖 텍스트는 개행 세탁·제어문자 제거 후 본문 SHA-256 nonce 펜스로 감싸 프롬프트 인젝션 지시 위조까지 방어한다(고정점 논증). 이 수준의 인젝션 방어를 갖춘 하네스 플러그인은 거의 없다.

04장점 품질 5.0

  • 2대 불변식이 설치 부담을 없앤다. 비간섭(.harness/ 없는 프로젝트에선 완전 침묵)과 무해(훅은 어떤 실패에도 exit 0 — 세션을 절대 깨지 않음). 전역 설치해도 opt-in 전까지 비용이 0이다.
  • 이벤트 소싱이 진짜로 구현됐다. "저널 먼저, 파생 캐시 나중" 순서 계약이 전 변이 경로에 일관 적용되고, 손상 시 재생 폴백 + 열화(degraded) 고지 + doctor 복구까지 닫혀 있다.
  • fail-open이 관측 가능하다. 침묵 흡수된 훅 실패는 반드시 .runtime/hook-errors.log에 남는다 — "하네스가 꺼진 걸 아무도 모르는" 상태를 설계적으로 배제.
  • 게이트 익스플로잇을 스스로 사냥했다. 빈 디렉토리로 UX 증적 게이트 통과, 웨이브 번호 재발급으로 남의 스크린샷 상속, 동시 생성 TOCTOU — 전부 주석에 공격 시나리오와 함께 방어가 박혀 있다.
  • 자기 프로세스로 자기를 출하했다. 동봉된 readiness 감사가 게이트 선확정·실측 근거(G1~G9)로 자체 판정 — 도그푸딩의 모범.
  • 에러 메시지마다 탈출 경로를 안내한다(원인 + 다음 명령) — CLI UX가 세심하다.

05단점

  • 한국어 전용. README·CLI·훅 주입 전부 한국어 — 마켓플레이스 배포 목표와 정면 충돌. 글로벌 상품화엔 i18n이 선결 과제.
  • 의식(ceremony) 비용. wave create → activate → update → complete + node upsert + 원장·페이즈·STALE 어휘 선학습. 짧은 작업엔 절차가 작업보다 무겁게 느껴진다.
  • 발견성 부족. 슬래시 커맨드가 없어 설치 후 "뭘 해야 하는지" 보이지 않는다 — 이 프로젝트의 progress.md에조차 "/king-wjang-harness 는 존재하지 않음" 혼동 기록이 남아 있다.
  • 훅 오버헤드. PostToolUse matcher가 * — 모든 도구 호출마다 node 프로세스 기동(실측 p95 104ms). 긴 세션에서 수백 회 누적된다. 치명적이진 않으나 공짜도 아니다.
  • 브랜치 병렬 작업과 마찰. .harness/가 git 커밋 대상이라 브랜치 전환 시 저널·웨이브가 함께 되감긴다. 잔존 증적 가드로 일부 방어했지만 events.jsonl 병합 충돌 시나리오는 미해결·미문서화.
  • 솔로 가정. 활성 웨이브 1개, 동시 세션·팀 협업 시나리오 없음. (타깃이 솔로 개발자라면 결함이 아니라 스코프.)
  • 배포 캐시 67MB — dist 자체완결인데 devDeps node_modules가 동봉된다. 다이어트 여지.

06가성비 4.0

비용: 훅 지연 100ms대 × 이벤트, SessionStart 주입 토큰 수백, 세션당 정산 명령 몇 건, 학습 1~2시간. 효익: 핸드오프 유실 1회 = 재탐색 수만~수십만 토큰 + 재작업 리스크. 웨이브 하나 정산하는 비용이 세션 하나 잃는 비용보다 두 자릿수 싸다.

손익분기는 "세션 3개 이상 걸리는 프로젝트" 근처다. 그 아래(일회성 스크립트·단일 세션 작업)에서는 순수 오버헤드지만, 비간섭 불변식 덕에 init 안 하면 비용이 정확히 0이라 — 하방이 막힌 투자다. 이 비대칭이 가성비 평가의 핵심.

07사용성 3.0

harness init 한 번이면 훅이 전자동이고, 이후 세션 주입·차단·정산 요구가 알아서 돈다 — 일단 궤도에 오르면 마찰이 낮다. 문제는 궤도에 오르기까지: 개념 어휘가 6개(페이즈·트랙·웨이브·원장·노드·STALE), 문서는 README와 설계 스펙뿐, 온보딩 튜토리얼·/harness 스킬·상태 HUD가 없다. "설치 → 침묵 → ???"의 골짜기를 메워줄 첫 10분 경험이 상품화의 최우선 과제.

08상품성 현재 2.5 → 전망 4.0

시장은 혼잡하다(superpowers·oh-my-claudecode·gstack 등). 그러나 기존 하네스 대부분이 프롬프트 지침 기반의 "소프트 규율"인 반면, 이 플러그인의 하드 강제 + 이벤트 소싱 무결성 + 인젝션 방어 조합은 실질 차별점이다. 포지셔닝 한 줄이 이미 나와 있다:

"AI가 설계 승인 전에 코드를 못 쓰게 물리적으로 막습니다 — 지침이 아니라 훅으로."

다만 현재 v0은 그 약속의 절반(게이트 미구현·한국어 전용·코어만 존재)이다. 상품이 되려면: ① 페이즈 게이트 구현으로 자기해제 구멍 봉인, ② 영문화, ③ 온보딩 스킬/커맨드, ④ 13페이즈 중 최소 설계 트랙의 산출물 스킬. 타깃은 명확하다 — 에이전트로 며칠~몇 주짜리 프로젝트를 굴리다 세션 단절·설계 폭주에 데인 솔로 개발자. 좁지만 아픔이 깊은 시장이라, 넓게 팔기보다 깊게 파는 쪽이 맞다.

09바이브코더 반응 예상

순수 바이브코더 — "일단 되게 해줘" 이탈 위험 높음

첫 deny에서 갈등. "설계 트랙에서는 소스 코드를 쓸 수 없다"는 바이브코딩의 안티테제다. 상당수가 "왜 내 AI를 막아?"라며 uninstall — 이 플러그인은 애초에 이들을 위한 물건이 아니다.

데인 경험자 — 에이전트 폭주로 프로젝트 망쳐본 사람 핵심 팬층

"Claude가 설계 무시하고 3시간 폭주한 뒤 되돌린 적 있다"는 사람에게 하드 차단은 정확히 원하던 것. Stop 가드의 정산 강제도 "다음 세션이 이어받는다"는 실익으로 받아들인다. 입소문의 진원지.

프로세스 지향 개발자 / PM 성향 열광

설계 원장·추적성·UX 증적 게이트·이벤트 저널에 반응. "드디어 에이전트 작업에 감사(audit) 가능한 궤적이 남는다." 코드 품질을 열어보고 신뢰를 굳히는 층.

플러그인 수집가 조용한 미온

설치 후 harness init을 몰라 "아무 일도 안 일어나는데?"로 끝날 확률이 높다 — 비간섭 불변식의 역설. 첫 실행 안내가 없으면 별점도 후기도 없이 잊힌다.

예상되는 밈 스펙트럼: "AI한테 잔소리하는 시어머니 플러그인" ↔ "드디어 Claude가 말을 듣게 됐다". 논쟁적 반응 자체가 마케팅 자산이 될 수 있는 유형이다.
